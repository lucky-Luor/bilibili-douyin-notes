# 课堂笔记模板与规范（bilibili-douyin-notes）

**版本：v1**（笔记 frontmatter 的 `template_version` 字段取此值；模板升级时递增）

本文件是本 skill 生成课堂笔记的**唯一模板与规范**，包含：完整 Markdown 骨架、
★ 语义定义、证据锚点规范、模板要点清单。不依赖任何个人本机文件，
任何人在任何机器上按本文件生成都应得到结构一致的笔记。

生成笔记后建议用 `scripts/validate_note.py` 做质量门禁（errors 必须为 0）。

---

## 一、证据锚点规范（必读）

每条关键论断都必须可回溯到视频里的具体时刻：

1. 每个小节的**关键论断/结论**后面用行内 `[mm:ss]` 标注视频时间点，
   推荐格式：`- ★★★ 要点句 [mm:ss]`、`……这一设计解决了 X 问题 [05:43]`。
2. **时间点必须来自转写稿/字幕里真实存在的 `[mm:ss]` 时间戳**，禁止编造。
   生成笔记前先在转写稿里确认该时间行存在（grep 即可）；转写稿时间是"该段话开始
   的时刻"，ASR 相对画面约有 1~3 秒滞后，引用时可小幅前移，但不得虚构不存在的时刻。
3. 文末可加 `## 参考时间戳` 附录，列出本讲关键节点（开场、重点切换、代码演示、总结），
   方便复习时直接跳转进度条。
4. 代码示例必须标注来源，二选一：
   - 来自视频：`来源：P06 [12:34]`（哪个分P、哪个时刻）；
   - 来自克隆的代码仓库：`来源：仓库 simplejava/src/main/java/demo/OrderService.java`
     （子项目 + 文件路径）。
5. 转写稿/字幕里没有的内容不要编造；确有必要补充时标注"（视频中未展开，建议补充）"。

## 二、★ 语义定义（写死，本 skill 独有机制）

| 标记  | 含义               | 判定标准                                                                 | 数量建议     |
|-----|------------------|----------------------------------------------------------------------|-----------|
| ★★★ | 核心概念 / 必考点     | 本讲的主线；合上笔记能独立复述才合格                                          | 每讲 2~4 个 |
| ★★  | 重要机制 / 易混淆点    | 与相邻概念有区别或常被误解（典型：BeanFactory vs ApplicationContext）            | 不限       |
| ★   | 补充了解             | 延伸知识、工具细节，考试不考但值得知道                                        | 不限       |

使用格式（★ 与证据锚点联用）：

```markdown
- ★★★ 要点句 [mm:ss]
- ★★ 要点句 [mm:ss]
- ★ 要点句
```

规则：

- ★ 数量只能是 1~3 个，写在要点句开头，后面空一格接要点句；
- ★★★ 的要点句必须是"完整可复述"的句子，不是关键词罗列；
- 同一小节内 ★★★ 不宜超过 2 个（整讲 2~4 个），避免"全是重点=没有重点"。

## 三、完整模板

```markdown
---
template_version: v1
---

# 课堂笔记 <序号>：<主题>

> 课程来源：<视频标题>（B站 <BV号> 或 抖音 <视频ID>，UP主/作者：<名字>，共N个小节约M分钟）
> 课程代码：<简介中的仓库地址，如有>

## 目录

- <按分P或知识点列出>

---

## <分P/小节名>（时长）

**核心思想：**<一句话>

- ★★★ <本节主线要点> [mm:ss]
- ★★ <易混淆点/对比要点> [mm:ss]
- ★ <补充了解>

<代码示例（真实代码 + 来源标注）……>

<概念对比用表格……>

---

## 本讲知识地图

<用一个 ASCII 图/缩进列表把本讲知识点串起来>

## 自测题（复习用）

1. <覆盖核心概念的问答题，附提示>（共 5~9 道）
2. ...

## 参考时间戳

- [mm:ss] <该时刻讲了什么>
- ...
```

## 四、模板要点清单

生成笔记时逐条核对：

- [ ] 文件开头有 frontmatter（`---` 包围），且含 `template_version: v1`；
- [ ] 按视频小节顺序组织，**每节标题标注时长**；
- [ ] 每节要点用 `★数量 + 要点句 + [mm:ss]` 格式，★★★ 每讲 2~4 个；
- [ ] 代码块用课程真实代码（来自文稿或克隆的仓库），并注明来源
      （子项目 / `[mm:ss]` / 仓库文件路径），不要凭空补写；
- [ ] 概念对比用表格（如 BeanFactory vs ApplicationContext）；
- [ ] 结尾必有"本讲知识地图"（ASCII 图或缩进列表）+"自测题"（5~9 道问答题，附提示）；
- [ ] 所有 `[mm:ss]` 都能在转写稿中找到对应时间行；
- [ ] 笔记里嵌入的截图用相对路径 `![说明](images/xxx.png)`；截图文件名**默认可中文**，
      需要 ASCII 文件名时给 bili_screenshot.py 加 `--ascii-names`（中文锚点 label
      自动转为 `zh-<md5前6位>`）；
- [ ] 生成后运行 `python scripts/validate_note.py <笔记.md>`，errors 为 0 才交付。
