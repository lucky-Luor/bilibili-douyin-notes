## 首次失败、方案调整与答案保真

首次 runner 执行在构造新增卡片的唯一插入点断言处失败，报“第一篇模板与预期不一致”。`i5-first-attempt-failure.json`、`i5-first-attempt-final.json` 和历史 `i5-failure.json` 保留该失败，未删除或改写为通过。`i5-runner-root-cause.json` 证明原 note 有 122 处 CRLF，硬编码 LF 的匹配数为 0，规范化后唯一匹配为 1。修复的是 runner 的换行处理，构造的 fixture 保留 CRLF；随后从头完整重试通过，最终以 `i5-final.json` 为准。

相对技术方案，digest 使用笔记文件的实际 hash 检出“改文件但未 mark”的变化；只用旧 `gate.sha256` 会漏掉这种变化。另纳入路径与标题，避免重命名后旧链接或标题仍被当成有效缓存。这些调整用于保证 `CR-STALE` 的实际行为，单集模板与门禁规则保持不变。

收尾检查发现，答案保真切片将 15 篇笔记最后一题后的 `---` 章节分隔线也带入答案。局部修复原本地提交为 `3fdfae5`，重建后为 `d7d791c`，已纳入 PR #50：保留答案正文、内部 Markdown 和内部 `---`，仅移除节末结构分隔线；不修改 `validate_note.py` 或原笔记。修复后重新生成副本并导出两个公开样例，`i5-final-export.json` 确认 33 概念、73 题、掌握 0、0 errors / 0 warnings，以及答案末尾分隔线泄漏数为 0。
